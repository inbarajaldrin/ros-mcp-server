## Critical Anti-Patterns (carry forward — discovered this session)

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Welding USD mesh vertices to enable smooth normals | RG2.usd ships fully unwelded with `faceVarying` authored normals. Trimesh `merge_vertices()` collapses sharp normal seams at recess edges (e.g. recessed bolt-holes on the gripper housing front face), making recess interiors face wrong → render dark. Symptom matched user's "black circle in centre of gripper above fingers + black rectangle above" report. | advisory | Use OBJ + MTL pipeline (no welding ever happens). If you must process the mesh, preserve the source's `faceVarying` normal authoring directly. See `~/.claude/skills/isaac-sim-extension-dev/references/usd-to-urdf-visualization.md`. |
| Multi-visual URDF + top-level `<material name>` reference | Documented RViz2 bug ([ros2/rviz#1293](https://github.com/ros2/rviz/issues/1293), [ros-visualization/rviz#843](https://github.com/ros-visualization/rviz/issues/843)) — only the first visual's material color is honored; subsequent visuals fail name lookup and default-grey. Looks like it works in some setups but is unreliable across versions. | advisory | Use OBJ + MTL pipeline — Assimp loads MTL automatically per `usemtl` group, no URDF parser involvement. |
| TF axis arrows mistaken for mesh red color | RViz's TF display draws red/green/blue axis arrows at every TF frame. With `tool0` and `rg2_base_link` colocated at the wrist, those red X-axis arrows appear at the gripper and confounded a "is the URDF color applying?" verification (GPT briefly reported "red is visible" when the actual mesh was default-grey). | advisory | Disable TF arrows / axes / names in the RViz config when verifying mesh colors. Re-enable after color is confirmed. |
| Claude's own visual judgment for subtle rendering quality | Several iterations during Phase 7 had Claude assert mesh rendering looked correct when GPT or operator visual diff disagreed. Faceting, color contrast, and recess artifacts are all hard to judge without ground-truth comparison. | advisory | Use the `ask-gpt` skill for visual diff — pass screenshots to GPT for ground-truth assessment. Or compare to Isaac Sim's render of the same asset as canonical truth. |
| Anchoring live-Isaac-Sim TF read on the wrong prim | When deriving the static TF for an accessory URDF, choosing the leaf rigid-body prim vs the asset root produces a clean ~90° error. The leaf may have its own `xformOp:orient` already encoded in the URDF mesh visuals; reading from the leaf double-counts that rotation. | advisory | Anchor the live read on the prim whose frame matches the URDF root link's frame. For RG2 specifically: `/World/RG2_Gripper` (asset root), NOT `/World/RG2_Gripper/onrobot_rg2_base_link` (leaf). See `~/.claude/skills/isaac-sim-extension-dev/references/external-urdf-tf-attach.md`. |
| Restarting `ros2 launch` immediately after killing | `urscript_interface` (from `ur_robot_driver`) doesn't honor SIGINT; escalates to SIGTERM after 5s, SIGKILL after 10s — total ~15s. If new launch starts before old one fully tears down, controllers fail to spawn (port/topic conflicts) and new launch dies silently. | advisory | After `pkill -SIGINT -f "ros2 launch"`, sleep 4s, then `pkill -SIGTERM -f "rviz2\|robot_state_publisher\|ros2_control_node\|static_transform_publisher\|urscript_interface\|controller_manager"`, sleep 5s, verify `ps -ef | grep -E "ros2_control|urscript|robot_state"` is empty before re-launching. |
