# RALPH-Pattern Phase: Each session does ONE chunk

> **This is a RALPH-style phase**: each Claude session reads `.planning/ralph_state.json`,
> picks the top task from `task_queue`, does ONE focused chunk of work,
> updates state, commits, exits. Fresh context each session avoids
> compression risk; disk is the persistent memory.

**On every session start:**
1. Read `.planning/ralph_state.json`
2. Read `.planning/insert_algorithm_research_2026-05-04.md` (full doc)

4. Read its `input_files`
5. Execute its `acceptance_criteria` (one chunk)
6. Move task to `completed_tasks` with verification notes
7. Commit
8. Exit

**Stop conditions** (do NOT keep working past these):
- Top task complete + acceptance criteria verified
- Token budget approaching limit (let next session pick up)
- Any unanticipated state requiring operator decision

**Anti-thrash:** consult `rejected_approaches` and `anti_thrash_rules` before any code change.

## CONTROL LOOP ARCHITECTURE

```
loop_iterate.py  →  iterate_insert.py  →  compliant_insert.py wrapper
  N consecutive       sets up rotate_object        FSM: APPROACH → FIND_HOLE
  successes           reads prev meta              → ENTRY_SETTLE → INSERT
                      forwards --hole-xy-prior     → DONE / ABORT
                      launches wrapper             with WEDGE_RECOVERY substate
```

Each layer wraps child in `os.setsid` for clean SIGTERM cascade.
