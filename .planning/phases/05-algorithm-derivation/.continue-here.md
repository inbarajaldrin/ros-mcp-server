## 5. The Mode B v3 spiral, explained in one screen

```
NORMAL state (post-contact):
    if at_seat (|tcp_z − predicted_seat_z| ≤ 5mm):
        do nothing — let predicate fire (motion_stopped + tcp_z_reached + descended_post_contact)
    elif stuck (net descent over 2s window < 0.5 mm/s AND fz_smooth > 6N, sustained 2s):
        if correction_count ≥ max_corrections (30): ABORT
        else: enter CORRECTING

CORRECTING state (1.5s burst):
    Phase A (first 0.15s — retract/unload):
        wrench = (0, 0, +2N, 0, 0, 0) base_link
        gain_scaling = 0.5, damping = 0.20
    Phase B (next 1.35s — spiral search):
        F_amp(t) = lerp(1.5, 4.0) over progress
        T_amp(t) = lerp(0.10, 0.30) Nm over progress
        theta = 2π × 1.5Hz × t_in_search
        bias_force = clip(400 N/m × ||target_xy − tcp_xy||, max=4N)
        bias_dir   = (target_xy − tcp_xy) normalized
        Fx = bias_force × bias_dir.x + F_amp × cos(theta)
        Fy = bias_force × bias_dir.y + F_amp × sin(theta)
        Fz = -3N
        Tx = T_amp × cos(theta), Ty = T_amp × sin(theta)
        gain_scaling = 0.5, damping = 0.20

    Per-tick (during the 1.35s search): track 100ms-windowed z descent rate.
        if descent rate ≥ 0.5 mm/s AND no hole_observed yet:
            HOLE DETECTED
            record hole_observed_xy = current tcp_xy
            return ("revert", {reason: "hole_detected", hole_xy, ...})
            → wrapper writes hole_observed into meta JSON
            → spiral ends early; default wrench (-9N Fz) takes over; peg drops into hole

COOLDOWN state (0.3s after burst):
    revert to nominal force mode (Fz = -9N, lateral = 0, gain = 1.0, damping = 0.7)

NORMAL again. Loop until predicate fires (success) or max_corrections hit (abort).
```

`target_xy` is computed in the wrapper each tick:
1. If `--hole-xy-prior X Y` was passed → use it (hole observed in a prior attempt, refined via cross-attempt persistence)
2. Else if CAD-derived prediction exists → use `predicted_tcp_at_seat.xyz_m[:2]` (this is now correct after today's cad_lookup refactor)
3. Else fall back to `ep.target_xyz` (hover xy ≈ assembly center xy)

The bias keeps the peg from drifting away from the best-available target, while the rotation searches the local neighborhood for the chamfer.

## 6. Tuning knobs to consider (likely needed for full 5×4 success)

The loop is currently running u_orange. If it's not converging:

### Knobs in `compliant_insertion_studio/configs/defaults.yaml` → `correction.action`

| Knob | Current | Tune up to | Tune down to | Why tune |
|---|---|---|---|---|
| `search_F_lat_end_N` | 4.0 | 6.0 | 2.0 | Bigger spiral force = more aggressive lateral exploration. Push higher if peg never breaks chamfer. Push lower if part is being shoved sideways too violently. |
| `search_T_lat_end_Nm` | 0.30 | 0.50 | 0.15 | Bigger torque = more tilt-counter. Helps if part is wedging at a tilt. |
| `search_F_lat_start_N` | 1.5 | 2.5 | 0.5 | Higher start = faster ramp. Lower = more gentle in-chamfer entry. |
| `search_freq_hz` | 1.5 | 2.5 | 0.8 | Higher = more lateral cycles per burst (peg passes through chamfer angle more often). Lower = more dwell per direction. |
| `duration_s` | 1.5 | 2.5 | 1.0 | Longer burst = more chances to find chamfer. |
| `cooldown_s` | 0.3 | 0.6 | 0.1 | Shorter cooldown = faster iteration but less time for peg to settle between bursts. |
| `search_bias_kp_N_per_m` | 400 | 800 | 0 (off) | Higher = stronger pull toward target_xy. 0 = pure exploration (peg can drift away from estimate). |
| `search_bias_max_N` | F_lat_end | 6.0 | 1.0 | Cap on bias force. |
| `retract_fz_N` | 2.0 | 4.0 | 1.0 | Bigger lift during unload phase. Helps if peg gets sucked into a wedge. |
| `retract_phase_s` | 0.15 | 0.30 | 0.05 | Longer unload before search. |
| `correction.stuck.min_descent_rate_m_s` | 0.0005 | 0.0010 | 0.0002 | Higher threshold = triggers correction sooner (more conservative). Lower = lets the peg grind longer before declaring stuck. |
| `correction.stuck.descent_window_s` | 2.0 | 1.0 | 3.0 | Smaller window = quicker stuck detection. |
| `correction.max_corrections` | 30 | 50 | 15 | More corrections per attempt = more chances. Capped at 50 for safety. |
| `spike_threshold_m_s` (in `cfg.correction`) | 0.0005 | 0.0010 | 0.0003 | Higher = only declare hole-detection on bigger spikes (less false positives). Lower = catch slower descents. |

## 8. CRITICAL anti-patterns (do NOT repeat — each cost time today)

| Pattern | Discovery | Mitigation (structural) |
|---|---|---|
| Skipping rotate_object between attempts | Operator observed iter 7 EE was at 4.7° pitch tilt — the post-cleanup retract holds whatever orientation the prior wedge ended in, and that propagates to subsequent attempts. | `loop_iterate` always passes `--already-held` for attempts 2+, which forwards to `run_assembly_step --already-held` which calls rotate_object every iteration. **Do not bypass this** with a "wrapper-only" mode. |
| Calling `python3 primitives/foo.py` (script-path) | Failed silently with `ModuleNotFoundError` because primitives import siblings. | Always use `python3 -m primitives.foo` (module mode). |
| Trusting `rotate_object`'s "Final EE orientation" log line as actual achieved | The log was the IK target, not the FK of the selected solution. IK was returning current joints with 5° pose error as a "solution". | Today's fix in `_select_best` enforces cost ≤ 0.025 → IK rejects loose solutions. Do not relax this threshold. |
| Reading object pose from camera while held | Gripper occludes camera. We chained orientation through primitive `__RESULT_JSON__` and rotate_object's HELD_QUAT output instead. | Never call `_read_base_pose` from a position where the robot occludes — base pose is config-fixed (`DEFAULT_BASE_POSITION`). |
| Pushing harder + cardinal force pokes to break wedges | 4 iterations × 12 corrections each ABORT'd. The wedge deepened each time. | Mode B v2/v3: retract + drop Fz to -2 to -4N + spiral search at lower gain (0.4-0.7) and damping (0.15-0.30). Action TYPE matters more than magnitude. |
| Detecting "stuck" from instantaneous v_z | Force-mode oscillation makes v_z dip below threshold spuriously. | Net z-descent over 2s window with Fz smoothed over 0.5s. |
| Counter-residual force direction for wedges | When peg is wedged at corner (-X,-Y), wrist sensor reads (+X,+Y) — counter-residual = AWAY from target. | Use TOWARD-target direction = `target_xy − tcp_xy` (CAD-derived or hole_xy_prior). Already implemented. |
